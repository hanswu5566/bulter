# Butler 智慧管家工具化轉型設計方案 (2026-03-08)

## 1. 核心願景 (Vision)
將 Butler 從「萬能但無章法」的聊天機器人，轉型為「情境感知、工具導向」的智慧租屋助理。
*   **去聊天化 (De-chat)**：大幅減少開放式對話，改以引導式按鈕交互。
*   **工具化 (Toolify)**：根據使用者當前頁面（情境）提供精準的功能選單。
*   **節省成本**：透過限制對話流與使用高效能模型組合，降低 Token 消耗。

## 2. 核心功能設計

### 功能 A：匹配診斷 (Match Diagnosis) - 針對房客
*   **觸發場景**：房源詳情頁 (`/listings/[id]`)。
*   **交互方式**：
    1.  Butler 依據 URL 偵測房源，主動問候並提供 `[🔍 進行匹配診斷]` 按鈕。
    2.  點擊後，AI 對比使用者標籤 (`profileTags`) 與房源特徵 (`features`)。
    3.  **輸出結果**：
        *   **評分制**：顯示契合度分數（如 85%）與文字摘要。
        *   **需求對應表**：條列展示「使用者需求」vs「房源事實」的匹配狀態（✅/⚠️/❌）。
*   **AI 模型**：Gemini 3 Flash (處理邏輯推理)。

### 功能 D：房源優化診斷 (Listing Optimization) - 針對房東
*   **觸發場景**：房源發布/編輯頁 (`/landlord/listings/create`)。
*   **交互方式**：
    1.  偵測使用者正在填表，提供 `[✨ 優化房源描述]` 按鈕。
    2.  **輸出結果 (診斷建議表)**：
        *   條列式建議（如：標題優化、缺失台水台電資訊、加分建議等）。
        *   不直接替房東修改內容，而是提供明確的修改方向。
*   **AI 模型**：Gemini 3 Flash (處理行銷與邏輯判斷)。

### 功能 C：實地看房清單 (Inspection Guide)
*   **觸發場景**：實勘頁面 (`/inspect/[id]`)。
*   **功能**：按部就班引導檢查細節（水壓、隔音等）。

## 3. 系統架構與互動邏輯

### 3.1 互動模型：引導式對話 (Guided Conversation)
*   **Butler 說話**：以對話氣泡形式呈現訊息。
*   **使用者回話**：移除自由文字輸入框，僅提供固定選項按鈕。
*   **情境感知**：Butler 監聽 `window.location.href` 自動更換選單內容。

### 3.2 AI 模型分配策略
*   **Gemini 3.1 Flash-Lite (門房)**：處理情境偵測、路由判斷、簡單問候。追求極速與低成本。
*   **Gemini 3 Flash (專家)**：處理匹配診斷、優化建議、邏輯推理。追求準確度。

## 4. UI/UX 變更
*   **移除輸入框**：預設不顯示 `input` 欄位。
*   **卡片式選單**：中間內容區動態切換「功能按鈕」、「診斷分數」、「數據表格」。
*   **底部操作**：增加「返回主選單」按鈕，方便在不同功能間跳轉。

## 5. 成功指標
*   平均對話輪數減少 50% 以上。
*   Token 消耗降低 40% 以上。
*   功能觸發率提升 30% 以上。
