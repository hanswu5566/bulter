## Introduction

| 「AI 租屋探照燈」是一個微型 SaaS (Micro-SaaS) 產品，以 Chrome Extension 的形式存在。它不試圖建立一個新的租屋平台，而是「寄生」在現有的主流平台（初期以 591 與 Facebook 租屋社團為主）之上，透過 AI 技術將原本混亂、隱蔽的文字與圖片數據結構化，解決台灣租屋族長期面臨的「資訊不對稱」問題。 |
| :---- |

## Problem Statement

| **當前流程**：台灣租客在尋找租屋時，需耗費大量時間瀏覽 591 或 Facebook 社團。<br>**痛點**：<br>1. **電費與稅務黑市**：房東超收電費，且常限制「不可報稅」、「不可申請租金補貼」。<br>2. **照片詐欺與隱患**：暗房、頂加、神明廳氣味、廣角變形。<br>3. **虛假距離**：假捷運宅。<br>4. **社團詐騙**：FB 上充斥假房東，要求看房前先付定金。<br>**解決方案**：利用 Gemini AI 的強大圖文解析能力，提供即時的房源透明度報告，並引入法規合規性與防詐騙檢查。 |
| :---- |

## Objective & Scope

| 大幅提升租客篩選房源的效率，將單一房源的評估時間從數分鐘降至秒級。透過透明的數據揭露與法規/詐騙比對，降低租客租到劣質、高風險或違法物件的機率。 |
| :---- |

Objective

### In-scope or Goals

| 1. 開發 Chrome Extension (Manifest V3)，能在 591 列表頁與詳情頁（以及 Facebook 社團頁面）注入自訂 UI。<br>2. 利用 Gemini API 進行費用、風險與發文者身分結構化。<br>3. 串接 Google Maps API 計算「真·通勤時間」。 |
| :---- |

### Not-in-scope or Non-Goals

| 1. 房東端功能（如自動發佈、房東儀表板）暫不在此 PRD 範圍內，優先專注於房客端功能。<br>2. 亦不涉入線上簽約與支付流程。<br>3. 初期暫不支援 591 與 FB 以外的平台。 |
| :---- |

## User Journeys (用戶旅程)

為了確保產品設計符合真實使用情境，我們定義了以下兩個核心用戶旅程：

### Journey 1: 高效租客的「秒殺」旅程 (主流程)
1.  **觸發**：用戶開啟 591 租屋網進行搜尋。
2.  **注入**：擴充功能自動在列表頁的每個房源卡片上標註「真·通勤時間」與「預估總支出」。
3.  **初篩**：用戶一眼看出哪幾間房子真正符合預算與時間成本（避開假捷運宅），點擊進入詳情頁。
4.  **深蹲**：側邊欄自動彈出「AI 診斷報告」，用戶查看 AI 對照片的診斷（採光、窗戶）與文本風險（是否頂加、是否可補貼）。
5.  **行動**：用戶對條件滿意，使用「AI 預約助手」一鍵生成客製化訊息，發送給房東。

## Assumptions

| 假設 591 與 FB 網頁的 DOM 結構不會在短時間內發生劇烈變更。同時假設 Gemini API 與 Google Maps API 成本在商業化後仍能維持在可接受的低點。 |
| :---- |

## Risks & Mitigations

| **風險**：平台封鎖（Anti-Scraping）。**緩解措施**：僅在用戶瀏覽時前端發送必要請求，減少後端依賴，利用快取。初期專注 591 與 FB，若遭封鎖可快速切換重心。<br>**風險**：AI 判斷失誤（Hallucination）。**緩解措施**：UI 明確標註免責聲明，並提供回報機制。 |
| :---- |

## Tradeoff 

| 考慮過建立獨立租屋平台，但雙邊市場建立難度極高。選擇 Chrome 擴充功能（寄生式 UI）能以極低成本獲取流量，快速驗證市場需求，雖然有被平台封鎖的風險，但作為 MVP 是最佳選擇。 |
| :---- |

## Business Benefits/Impact/Metrics

| **獲利模型 (Paywall 規劃)**：<br>1. **免費版**：每日限制解析 5 次，僅提供基礎數據結構化。<br>2. **付費版 ($299/月)**：無上限查詢，解鎖「真·通勤時間」與「AI 視覺屋況診斷」及「預約助手」。 |
